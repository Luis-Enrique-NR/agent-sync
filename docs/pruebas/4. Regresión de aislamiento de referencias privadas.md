# Regresión de aislamiento de referencias privadas

- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `backend/ai`
- **Incidente:** `UNKNOWN_PRIVATE_REFERENCE` seguido de `GUARDRAIL_RETRY_EXHAUSTED`

## Flujo que produjo el incidente

La ejecución fue:

```powershell
cd backend
python -m ai.tui --scenario p2p --provider openai --timeout-seconds 300
```

Secuencia observada:

```text
Valentina propone 300 USD y coordinar un encuentro
        ↓
AgentTurn incluye referencias propias de PHONE y MEETING_POINT
        ↓
MANDATORY_PERSONAL_DATA + USER_RULE
        ↓
La persona aprueba
        ↓
El contrato anterior copiaba las referencias al transcript
        ↓
El prompt de Mateo recibía referencias que no le pertenecían
        ↓
Mateo intentaba reutilizarlas
        ↓
UNKNOWN_PRIVATE_REFERENCE × 2
        ↓
GUARDRAIL_RETRY_EXHAUSTED
```

El guardrail falló de forma cerrada: el turno de Mateo nunca fue publicado y no se mostró ningún teléfono o ubicación real. La causa estaba antes del guardrail, en la serialización del transcript para la contraparte.

## Corrección verificada

La regresión automatizada reproduce el límite completo:

1. Valentina genera una oferta con dos `ProposedDisclosure` propios.
2. El motor pausa y emite `APPROVAL_REQUIRED` con audiencia `INTERNAL`.
3. La prueba confirma que el evento interno conserva la referencia necesaria para la decisión.
4. Se aprueba el candidato.
5. El transcript que recibe Mateo no contiene ninguna referencia de Valentina.
6. Mateo puede emitir un `DataRequest` por categoría sin demostrar propiedad sobre el dato pedido.
7. Todos los eventos `PUBLIC` son `TURN_READY` y ninguno contiene `_ref_`.
8. Un teléfono o una referencia opaca escondidos en `DataRequest.purpose` son bloqueados antes de publicar.

Una segunda prueba inspecciona directamente el prompt producido por `OpenAIProvider` con un cliente falso. Confirma que conserva `PHONE` y `MEETING_POINT` como categorías útiles, pero excluye `contact_ref_valentina_phone` y `location_ref_public_meeting_point`.

## Criterios de seguridad

- Una solicitud a la contraparte no porta `value_ref`.
- Una divulgación propuesta solo acepta referencias del hablante.
- Una referencia puede existir en el contexto privado del propietario y en eventos internos de aprobación.
- Ninguna referencia entra al transcript público, a `TURN_READY` o al prompt posterior de la contraparte.
- Un candidato inválido sigue bloqueándose aunque el prompt del modelo no obedezca las instrucciones.
