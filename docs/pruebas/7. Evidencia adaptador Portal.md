# Evidencia adaptador Portal
- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `fix/portal-access-administration`

## Contexto
El adaptador debe ejecutar publicación y acceso autorizados y documentados, sin red real ni credenciales.

## Evidencia
Corrección 2026-08-08: las pruebas de acceso se escribieron antes de extender el adaptador. El primer intento no pudo ejecutar `python` porque el alias de Windows no tenía intérprete; con el intérprete gestionado, una aserción de path expuso que `httpx.URL.path` decodifica la ruta. Se corrigió la prueba para verificar `raw_path`, que es el contrato de codificación transportado. La corrección de validación añadió RED para `PortalRetryable`; GREEN: `python -m pytest tests/test_portal_client.py` produjo `11 passed`.

`httpx.MockTransport` verifica método, `raw_path` codificado, bearer, el cuerpo único exacto `{userId, claims}` y el batch `members`, además de `expiresAt`. También verifica `added` entero estricto (rechaza ausencia, booleano y string), respuestas vacías idempotentes, error `{code, reason}`, clasificación retryable de `429`/`503` sin reintento y una sola llamada ante timeout. El fake devuelve el mismo `CommandApplied` para acceso y `PublishedMessage` para publish, sin red.

## Riesgos y pendiente
No se usaron llaves ni mutaciones de Portal. Las rutas de miembros y bans ya están documentadas y se implementan; cualquier forma fuera de la unión cerrada sigue rechazada sin llamada. Las pruebas no sustituyen la provisión operativa futura.
