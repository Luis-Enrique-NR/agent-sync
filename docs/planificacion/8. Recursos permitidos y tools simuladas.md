# Recursos permitidos y tools simuladas

**Estado:** Aceptada

**Fecha:** 2026-08-09

**Rama de implementación:** `frontend`

## Contexto

La interfaz anterior presentaba recursos genéricos como si todos estuvieran disponibles. El backend, en cambio, solo expone parte del catálogo mediante adaptadores mock o MCP. Para el MVP la pantalla debe demostrar el flujo de permisos y aprobaciones sin afirmar que existen integraciones reales.

## Decisión de producto

La configuración se divide en dos grupos:

- **Fuentes de información:** consultas de solo lectura que pueden ejecutarse automáticamente.
- **Acciones externas:** operaciones que crean mensajes, reuniones o cambios fuera de AgentSync y siempre requieren aprobación humana.

Cada recurso muestra un estado honesto (`Simulado`, `Conectado`, `No configurado` o `Error`), su alcance, el modo de aprobación, la última ejecución, un consumo aproximado y una prueba local. En el MVP, `Probar recurso` solo simula una respuesta; no usa cuentas, credenciales ni proveedores reales.

## Catálogo representado en frontend

| Recurso visible | Identificador previsto | Efecto | Estado MVP | Modo inicial |
|---|---|---|---|---|
| Búsqueda de oportunidades | `web.search` | Lectura | Simulado | Automático |
| Disponibilidad de calendario | `calendar.check_availability` | Lectura | Simulado | Automático |
| Precios de referencia | `market.reference_prices` | Lectura | No configurado | Deshabilitado |
| Inventario y disponibilidad | `inventory.check_stock` | Lectura | No configurado | Deshabilitado |
| Solicitar una reunión | `calendar.request_meeting` | Acción externa | No configurado | Deshabilitado |
| Enviar una notificación | `email.send_notification` | Acción externa | Simulado | Preguntar siempre |

La interfaz no permite seleccionar `Automático` para una acción externa. Un recurso `No configurado` permanece deshabilitado hasta que el backend registre su tool correspondiente.

## Contrato temporal del frontend

`AgentTool` incorpora de forma opcional los campos `effect`, `approval_mode`, `connection_status` y `scope`. Son una representación local para el mock y deberán sustituirse por el contrato de grants servido por la API.

El frontend solo almacena la selección visual del usuario. No debe:

- ejecutar tools directamente;
- recibir tokens o secretos MCP;
- decidir por sí solo si una acción sensible está autorizada;
- convertir el botón de prueba en una conexión real sin confirmación del backend.

## Consecuencias y riesgos

La configuración gana claridad y puede probarse de punta a punta con mocks, pero sus estados de ejecución y consumo todavía son datos ilustrativos. El principal riesgo es que el catálogo visual se separe nuevamente del registro de tools; por eso, la API deberá convertirse en la fuente única para nombres, disponibilidad y alcance antes de conectar proveedores reales.

## Deuda técnica del backend

1. Registrar `market.reference_prices`, `inventory.check_stock` y `calendar.request_meeting`.
2. Exponer un catálogo de tools con efecto, estado, alcance y capacidades del proveedor.
3. Persistir cada selección como un `tool_grant` del agente.
4. Enviar las acciones sensibles a la bandeja de decisiones antes de ejecutarlas.
5. Guardar llamada, resultado, error, aprobación y consumo en auditoría.
6. Cuando se adopten servidores MCP reales, configurar endpoints, secretos, allowlists, health checks y límites exclusivamente en backend.

## Archivos frontend implicados

- `frontend/components/AgentSetupForm.tsx`: catálogo, agrupación, permisos y prueba simulada.
- `frontend/components/Icons.tsx`: iconografía de recursos.
- `frontend/lib/types.ts`: forma temporal de los grants.
- `frontend/data/mockData.json`: configuración simulada del agente activo.
- `frontend/app/globals.css`: presentación responsive del panel.

## Criterios de aceptación

- La palabra `Demo` no se usa como estado de conexión; se muestra `Simulado`.
- Las consultas y las acciones externas se distinguen a simple vista.
- Las acciones externas no pueden configurarse como automáticas.
- Los recursos inexistentes en backend se muestran como `No configurado` y no se pueden activar ni probar.
- Ninguna credencial o integración real se representa o ejecuta desde el frontend.
