# Plan de acción generado

- **Estado:** Completada
- **Fecha:** 2026-08-07
- **Rama:** `backend/ai`
- **Dominio:** AI Backend (`/backend/ai`)

## Contexto

El PRD exige un motor real de conversación agente-agente, límites de ejecución, guardrails determinísticos, escalamiento configurable y datos mock para B2B y P2P. El SRD asigna esta responsabilidad al dominio `/backend/ai`, pero el repositorio comenzó sin implementación.

## Plan mínimo

1. Definir contratos estrictos para perfiles, turnos, sesiones y decisiones humanas.
2. Aislar el proveedor de LLM detrás de una interfaz y agregar un proveedor falso para pruebas.
3. Crear un grafo de negociación con máximo de turnos y timeout.
4. Validar cada candidato antes de emitirlo mediante políticas determinísticas.
5. Pausar antes de publicar una decisión sensible y permitir aprobar, rechazar o reemplazar.
6. Probar el mismo motor con fixtures B2B y P2P.
7. Entregar una fachada independiente de REST, persistencia y Portal.

## Criterios de salida

- Ningún turno se emite antes de pasar schema, guardrails y reglas de escalamiento.
- Un precio fuera de un límite duro nunca aparece en el transcript público.
- Teléfono, email, dirección exacta y ubicación requieren aprobación humana.
- La sesión no puede ejecutar más turnos que el máximo configurado ni superar su deadline.
- Aprobar una decisión emite el candidato una sola vez; rechazarlo no lo publica.
- Las pruebas normales no llaman a un LLM real.
- Los escenarios B2B y P2P no bifurcan la lógica por `entity_type`.

## Fuera de alcance

Matchmaking, REST, persistencia, webhooks de Portal, UI, autenticación e integraciones reales con CRM o calendarios pertenecen a otros dominios.

## Resultado

El primer corte funcional quedó implementado en `/backend/ai` con contratos Pydantic, grafo acotado, adaptador real, proveedor falso, guardrails, reglas de escalamiento, reanudación humana y fixtures para ambos verticales. La validación quedó registrada en `docs/pruebas/1. Validación del primer corte AI Backend.md`.
