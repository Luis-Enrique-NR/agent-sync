# Evolución del AI Brain para el flujo multiagente

- **Estado:** Propuesta
- **Fecha:** 2026-08-08
- **Rama:** `backend/ai`
- **Origen:** caso de uso de agente con varias negociaciones, tools y decisiones tardías

## Contexto

El caso de producto amplía el loop actual hacia múltiples conversaciones, espera humana prolongada, revalidación de propuestas, capacidades externas y seguimiento de objetivos. Esta propuesta ordena el trabajo necesario sin cambiar los límites de responsabilidad definidos por el SRD.

## Objetivo

Evolucionar el AI Brain sin absorber las responsabilidades de matchmaking, transporte o persistencia. El resultado debe permitir que un agente procese varias negociaciones independientes, espere decisiones humanas durante un tiempo no determinado, revalide propuestas y reporte progreso del objetivo.

## Brechas respecto al corte actual

- El escalamiento se aplica principalmente desde la perspectiva del hablante.
- Un único deadline combina tiempo de ejecución y espera humana.
- Aprobar publica el candidato pendiente sin revalidar su vigencia.
- `ACCEPT` puede resolver la sesión sin un protocolo explícito de revisión bilateral.
- Los facts mock se inyectan como contexto y todavía no son tools ejecutables.
- No existe contrato de progreso o finalización del objetivo.
- El motor procesa una sesión aislada sin snapshot de compromisos en otras conversaciones.

## Corte mínimo demostrable

Para validar el caso sin construir un marketplace masivo:

1. Cargar un agente comprador y dos vendedores guionados.
2. Abrir dos sesiones independientes.
3. El vendedor A solicita una reunión y activa la regla sensible del comprador.
4. Avanzar un reloj falso una semana y retirar la propuesta de A.
5. Intentar aprobar y comprobar que el motor revalida y no publica el candidato vencido.
6. Continuar la sesión con el vendedor B hasta un acuerdo válido.
7. Emitir `GOAL_PROGRESS_REVIEW_REQUIRED`.
8. Probar `CONTINUE` para un vendedor con stock restante y `COMPLETE` para un objetivo único.
9. Opcionalmente consultar una búsqueda o inventario mediante una tool mock.

Este escenario demuestra asincronía, tolerancia al fallo de una oportunidad, concurrencia conceptual y control humano sin depender todavía de correo real, internet real o miles de agentes.

## Dependencias con los otros roles

| Necesidad | Responsable principal | Contrato esperado por AI Backend |
|---|---|---|
| Anunciar el agente y encontrar interesados | Dominio/Orquestación + Transporte | Manifest público y lista de candidatos. |
| Mantener varias sesiones y despertarlas | Dominio/Persistencia/Orquestación | Estado, evento y versión actuales. |
| Recibir retiro o cambio de stock | Transporte + Dominio | Evento autenticado e idempotente. |
| Reservar inventario u horario | Dominio/Persistencia | Resultado transaccional versionado. |
| Entregar notificación por correo | Transporte/Integración | Consumir `APPROVAL_REQUIRED` o `NOTIFICATION_REQUESTED`. |
| Renderizar decisiones y objetivo | Frontend | Eventos y comandos de decisión estructurados. |

## Definición de terminado del siguiente corte

- Las políticas entrantes y salientes tienen pruebas independientes.
- El tiempo humano no consume el timeout del LLM.
- Una aprobación tardía siempre revalida cuando la propuesta pueda estar obsoleta.
- Un retiro remoto puede cerrar una sesión pendiente sin corromper el historial.
- Dos sesiones del mismo agente pueden avanzar sin compartir transcripts ni referencias privadas.
- Las aceptaciones apuntan a una revisión exacta.
- El progreso del objetivo requiere confirmación antes de persistirse.
- Las tools mock obedecen grants, timeout y política de efectos.
- Los eventos públicos siguen sin referencias privadas ni payloads internos.

## Fuera de alcance inmediato

- Broadcast real a todos los agentes del ecosistema.
- Descubrimiento masivo y ranking semántico en producción.
- Envío real de correos.
- Integraciones reales de calendario, CRM o inventario.
- Conexión dinámica a servidores MCP arbitrarios.
- Resolución distribuida completa entre organizaciones independientes.
