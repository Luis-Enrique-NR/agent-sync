## Contexto
La planificación anterior asumía `origin/codex/ai-backend`. La base ejecutable real es `origin/backend/ai` en `5dc00c5`, incorporada por el tracker `094c444`; la cadena continuó con `ba3158e` (admisión), `640cd3e` (bus) y `ce14323` (adaptador). Transporte no modifica ni posee `backend/ai`.

## Avance concreto
Las pruebas y documentación de las tres unidades están completas. Redis de prueba corre en `agent-sync-redis` para la base 15; no es la propiedad operativa de producción. Portal documenta webhooks a nivel de proyecto: configurar `webhooks.url` en `portal.config.ts` con la URL HTTPS pública que termina en `/webhooks/portal` y ejecutar `portal deploy`. La activación crea el secreto por entorno; el servidor lo recupera mediante `GET /v1/webhooks/secret` con `Authorization: Bearer <PORTAL_SECRET_KEY>`.

## Consecuencias, riesgos y pendiente
La configuración de Portal y la asignación de propietario de Redis no fueron autorizadas para ser ejecutadas desde esta rama. Antes de activar la ruta o consumidores, el responsable operativo debe: (1) asignar propietario, persistencia, backup y alertas para Redis y establecer `REDIS_URL`; (2) desplegar la configuración de webhook pública; (3) guardar `PORTAL_SECRET_KEY` solo en el secret store del servidor; (4) comprobar desde el servidor que el secreto se obtiene y que el callback recibe un evento firmado. Un 404 del secreto indica que el webhook no está activado. No registrar ni copiar secretos en documentos, repositorio o frontend.
