# Integración end-to-end con estado compartido (Iteración 6)

- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `frontend`
- **Dominio:** Frontend UI (`/frontend`)

## Contexto

Hasta la Iteración 5 cada vista manejaba estado local aislado: resolver una decisión en la bandeja no se reflejaba en el chat, dashboard o historial. El PRD exige que el humano tenga el control total y que ninguna decisión sensible se publique sin su aprobación, con trazabilidad. Esta iteración unifica el "resolver" de decisiones (y la pausa de agentes) en una única fuente de verdad para la demo: un **store de estado compartido** que simula el contrato del resolver real del backend.

## Avance registrado

- **`lib/store.tsx`** (cliente): `AgentSyncProvider` + hook `useAgentSync`.
  - Estado global de `agents` y `sessions` derivado del mock.
  - `resolveDecision(sessionId, status)`: fuente única del resolver. Actualiza `pending_decision.status`, pasa la sesión a `RESOLVED` (y revela contacto) o `REJECTED`, de forma idempotente.
  - `toggleAgentActive(agentId)`: pausa/continúa un agente de forma global.
  - `resetDemo()`: vuelve al mock inicial.
  - **Persistencia en `localStorage`** (clave `agentsync-demo-v2`): el estado sobrevive a recargas y navegación.
- **`AgentSyncProvider` montado en `app/layout.tsx`**: envuelve toda la app.
- **Vistas refactorizadas a cliente consumiendo el store**:
  - `DashboardView` (`/`): métricas, panel de atención y tarjetas reaccionan al store (resolver en bandeja vacía el panel al instante).
  - `BandejaView` (`/bandeja`): contador y `DecisionInbox` usan el store; resolver ahí se refleja en chat e historial.
  - `ChatView` (`/chat/[id]`): server page delgada valida existencia y delega; el transcript lee la sesión del store y su `ConversationView` resuelve contra `resolveDecision`.
  - `HistorialView` (`/historial`): matches/rechazadas se calculan del estado vivo; una decisión aprobada desde la bandeja aparece como match al momento.
  - `EcosistemaList` (`/ecosistema`): el badge activo/pausado refleja `agent.active` del store (pausar en el dashboard se ve aquí).
  - `AgentStatusCard`: pausar/continuar llama a `toggleAgentActive`.
- `DecisionPanel` pasó a **controlado**: ya no guarda estado interno; renderiza según `decision.status` y notifica `onResolve`, que en todas las vistas ahora es el store.

## Consecuencias y riesgos

- El `localStorage` puede quedar con estado viejo de versiones previas; `resetDemo()` permite volver al mock y el sufijo `-v2` invalida versiones anteriores.
- El store es la simulación del resolver real. Cuando exista el Backend API / Portal, `resolveDecision` y `toggleAgentActive` deben reemplazarse por llamadas HTTP y la persistencia local por la del servidor.
- `ConversationView` conserva su streaming simulado localmente, pero la resolución final es del store; si una sesión ya está resuelta (desde la bandeja), se abre directamente en fase final sin reproducir el streaming.

## Trabajo siguiente

- Conexión real con el Backend API (AI Brain / Portal) cuando exista el contrato: sustituir el store de mock por llamadas HTTP y suscripciones de eventos (`TURN_READY`).
- Pruebas de humo del flujo completo en vivo durante la demo: configurar → negociar → decidir desde la bandeja → ver match en historial.
