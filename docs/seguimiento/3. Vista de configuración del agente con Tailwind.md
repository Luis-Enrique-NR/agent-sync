# Vista de configuración del agente con Tailwind

- **Estado:** Completada
- **Fecha:** 2026-08-07
- **Rama:** `frontend`
- **Dominio:** Frontend UI (`/frontend`)

## Contexto

El PRD define la Configuración del Agente como el corazón del producto (personalidad, objetivos, tools mockeadas, límites duros y reglas de escalamiento configurables por el usuario). La vista inicial de `/setup` era un placeholder estático; este corte la convierte en la vista principal funcional con Tailwind CSS.

## Avance registrado

- Tailwind CSS v4 integrado en el proyecto (vía `@tailwindcss/postcss` + `@import "tailwindcss"`), según la guía local de Next.js 16.
- Layout raíz y shell migrados a utilidades de Tailwind; el CSS global queda solo con variables de tema y primitivas de dashboard/ecosistema/chat.
- `components/AgentSetupForm.tsx`: formulario cliente completo:
  - Selector de **tipo de entidad** (B2B empresa / P2P persona) que precarga el perfil del agente correspondiente desde `mockData.json`.
  - Campos de **nombre/entidad, personalidad y objetivos** (uno por línea).
  - **Límites duros** dinámicos por entidad (precio máx. por unidad/volumen vs. precio mín. de venta/protección de dirección y teléfono).
  - **Checkboxes de decisión sensible** consumidos de `sensitive_categories` del mock: obligatorias no desactivable + editables a criterio del usuario.
- Al guardar se simula el consumo del perfil: se arma el payload `POST /api/agents` (con delay de red simulado) y se muestra la fusión de referencia con el mock (segmento y sesión de ejemplo B2B/P2P).

## Consecuencias y riesgos

- El consumo es simulado en el cliente; el `POST /api/agents` real debe apuntar al Backend API cuando exista.
- Los checkboxes obligatorios están bloqueados en la UI, alineados con la política de seguridad del PRD (categorías mínimas no desactivables).
- Las utilidades de Tailwind usan variables CSS del tema existente; el dark/light mode se mantiene por `prefers-color-scheme`.

## Trabajo siguiente

- Persistir la configuración vía Backend API y derivar de ella el estado real del agente en el dashboard.
- Validar en `/setup` que los límites numéricos se crucen con los guardrails del AI Backend antes de activar el agente.
