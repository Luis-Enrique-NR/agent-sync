# Dashboard y Ecosistema (Iteración 2)

- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `frontend`
- **Dominio:** Frontend UI (`/frontend`)

## Contexto

El PRD (§6) define el Dashboard como "solo lo esencial: estado del agente + qué requiere mi atención ahora" y el Ecosistema como una lista simple de agentes/negociaciones. La base anterior dejó ambas pantallas funcionando con estilos primitivos; esta iteración las convierte en vistas pulidas con Tailwind y agrega la interacción mínima de control (pausar agente) y filtrado por segmento.

## Avance registrado

- **Dashboard** (`/`):
  - `AgentStatusCard` (cliente): estado del agente (activo/pausado) con botón de **pausar/continuar** (historia P1 del PRD) y contador de decisiones pendientes.
  - Métricas: decisiones pendientes, agentes activos y negociaciones en curso.
  - **Panel "Qué requiere tu atención"**: lista de sesiones `PENDING_HUMAN_APPROVAL` con categoría y propuesta, enlazando a `/chat/[id]`.
  - Tarjetas de negociación con badge de estado, avance de turnos (barra de progreso) y conteo de mensajes.
- **Ecosistema** (`/ecosistema`):
  - `EcosistemaList` (cliente) con **filtro por segmento** (Todos / B2B / P2P).
  - Tarjetas de agente con personalidad, objetivos, tools y negociaciones activas derivadas de `mockData.sessions`.

## Consecuencias y riesgos

- Pausar/continuar es estado local; el control real debe enviarse al Backend API cuando exista el contrato.
- El filtrado y conteos se calculan sobre `mockData.json`; al conectar la API, deben derivarse del backend.
