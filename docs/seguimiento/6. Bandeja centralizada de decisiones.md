# Bandeja centralizada de decisiones (Iteración 4)

- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `frontend`
- **Dominio:** Frontend UI (`/frontend`)

## Contexto

El PRD exige que el usuario apruebe toda decisión sensible y que nada se publique sin su visto bueno. Hasta ahora las decisiones se resolvían dentro de cada conversación (`/chat/[id]`), pero con varios agentes activos el usuario no tiene una vista única de "todo lo que espera por mí". Esta iteración agrega una bandeja central donde se listan y resuelven todas las propuestas sensibles pendientes, conectada a la misma lógica de `DecisionPanel`.

## Avance registrado

- **Ruta nueva `/bandeja`** (`app/bandeja/page.tsx`): página de servidor que agrupa las decisiones pendientes derivadas de `mockData.sessions` con contador de pendientes.
- **`DecisionInbox`** (cliente): núcleo de la iteración.
  - Recolecta de todas las sesiones las que están `PENDING_HUMAN_APPROVAL` con `pending_decision.status === "PENDING"`.
  - **Filtro por segmento** (Todas / B2B / P2P) con conteos en cada chip.
  - Cada tarjeta muestra segmento, resumen de la negociación, quién la solicitó, enlace a la conversación completa y un `DecisionPanel` reutilizado para **Aprobar / Rechazar / Responder manualmente**.
  - Estado vacío con mensaje de "bandeja al día" (y conteo de decisiones resueltas en la sesión).
  - Estado de resolución local por sesión para la demo.
- **Dashboard**: el panel "Qué requiere tu atención" ahora incluye el enlace "Abrir bandeja →".
- **Nav**: nuevo ítem "Bandeja" en el header.

## Consecuencias y riesgos

- El resolver la decisión en la bandeja es estado local y no sincroniza aún con la conversación abierta en otra pestaña. Con el resolver real (Backend API / Portal), la bandeja y el chat deben compartir el mismo estado para evitar divergencias.
- `DecisionInbox` deriva las pendientes de `pending_decision`; cuando exista API, se debe consultar el endpoint de decisiones pendientes en lugar de derivarlas del mock.

## Trabajo siguiente

- Integrar bandeja y chat con el mismo resolver real (Backend API / Portal) cuando el contrato exista.
