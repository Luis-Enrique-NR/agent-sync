# Conversación agente-agente en vivo (Iteración 3)

- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `frontend`
- **Dominio:** Frontend UI (`/frontend`)

## Contexto

El PRD exige transparencia total en la conversación agente-agente (es requisito de confianza) y que el usuario pueda ver, pausar y corregir en cualquier momento. La base dejó `/chat/[id]` como transcript estático. Esta iteración lo convierte en una conversación viva que demuestra el loop completo: agentes hablando → decisión sensible → el humano aprueba → match.

## Avance registrado

- `mockData.json`: cada sesión activa ahora tiene `pending_script` (turnos que aún no han ocurrido). El mensaje que dispara la decisión sensible quedó movido ahí para que aparezca "en vivo" durante la demo.
- `ConversationView` (cliente): núcleo de la iteración.
  - **Streaming simulado** de turnos (delay de red) con indicador de "escribiendo…" del agente que habla y auto-scroll.
  - **Pausar/Continuar** la conversación en cualquier momento.
  - Badge de fase: en vivo, pausada, esperando decisión, match confirmado, descartada.
  - Mensajes marcados con **flag de decisión sensible** (⏸) y con **guardrail** (bloqueado, nunca emitido).
  - Al llegar al mensaje sensible: la conversación se congela y se muestra el `DecisionPanel`.
  - Al aprobar: continúa el script y termina en banner de **match**; al rechazar: sesión `REJECTED`.
  - Estado vacío con animación de "buscando agentes" para sesiones `SEARCHING`.
- `DecisionPanel` migrado a Tailwind y con callback `onResolve` para notificar al transcript.
- `app/chat/[id]/page.tsx` simplificada: cabecera con resumen y delegación a `ConversationView`.

## Consecuencias y riesgos

- El streaming es simulado en el cliente (timers). La fuente real será `TURN_READY` vía Portal cuando exista; `ConversationView` se diseñó para reemplazar el timer por eventos.
- El auto-play arranca al montar; con datos reales debe respetar el turno que corresponde y no duplicar mensajes en cada recarga.
- El `pending_script` es data de demo; el backend no debe depender de él.
