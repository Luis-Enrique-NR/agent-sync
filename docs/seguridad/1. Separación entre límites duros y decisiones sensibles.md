# Separación entre límites duros y decisiones sensibles

- **Estado:** Aceptada
- **Fecha:** 2026-08-07
- **Rama:** `backend/ai`

## Problema

Un límite inquebrantable y una acción permitida con consentimiento humano tienen comportamientos distintos. Representarlos con una sola bandera permitiría aprobar accidentalmente algo que nunca debía ocurrir.

## Decisión

- Un **límite duro** no puede ser aprobado. El candidato se bloquea antes de ser emitido y el motor puede pedir una regeneración acotada.
- Una **decisión sensible** puede ejecutarse después de aprobación explícita. El candidato queda pendiente y no se incorpora al transcript público mientras espera.
- Teléfono, email, dirección exacta y ubicación en tiempo real siempre se escalan, aunque el perfil no traiga una regla de usuario.
- Los valores privados no ingresan al contexto del LLM. Cuando un agente es el hablante, el modelo solo conoce las referencias opacas que le pertenecen; esas referencias no entran al transcript público ni al contexto de la contraparte.
- El texto público se escanea como defensa adicional, pero los campos estructurados son la fuente principal para validar números y acciones.

## Consecuencias

Los datos mock privados contienen categoría y referencia, nunca el valor secreto. Backend API necesitará un almacén o fixture separado para resolver esas referencias durante la demo.
