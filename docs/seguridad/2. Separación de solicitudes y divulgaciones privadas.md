# Separación de solicitudes y divulgaciones privadas

- **Estado:** Aceptada
- **Fecha:** 2026-08-08
- **Rama:** `backend/ai`
- **Componentes:** contratos de dominio, proveedor OpenAI, motor y eventos

## Contexto

Una prueba P2P real reveló una ambigüedad en el contrato anterior. El turno de Valentina proponía compartir `PHONE` y `MEETING_POINT` y contenía sus referencias opacas. Tras la aprobación humana, el motor copiaba esas referencias al transcript. El siguiente prompt, ahora para Mateo, serializaba el transcript completo y le mostraba referencias privadas que no le pertenecían.

Mateo intentó reutilizarlas y el guardrail respondió `UNKNOWN_PRIVATE_REFERENCE` dos veces. Al agotar el reintento, la sesión terminó de forma segura con `GUARDRAIL_RETRY_EXHAUSTED`. No se expuso el teléfono ni la ubicación reales, pero sí existía una fuga de identificadores opacos entre agentes.

## Decisión

Se separan dos intenciones antes representadas por un solo contrato:

- `DataRequest(category, purpose)`: el hablante pide a la contraparte una clase de dato. Nunca incluye una referencia.
- `ProposedDisclosure(category, value_ref, purpose)`: el hablante propone divulgar un dato propio. El guardrail exige que la referencia pertenezca a su manifiesto privado.

El `AgentTurn` puede contener ambos contratos, pero el `TranscriptMessage` público no conserva `ProposedDisclosure.value_ref`. Al publicar un turno aprobado se guardan el mensaje, los términos, las solicitudes y las categorías divulgadas, nunca la referencia opaca.

## Audiencias de eventos

Cada `EngineEvent` declara una audiencia:

- `INTERNAL`: aprobación, candidato bloqueado, decisión y ciclo de vida. Puede contener información de auditoría y no puede enviarse a la contraparte.
- `PUBLIC`: contenido autorizado para transporte. En este corte solamente `TURN_READY` recibe esta audiencia.

La integración deberá comprobar simultáneamente `event_type == TURN_READY` y `audience == PUBLIC`. No debe inferir que cualquier evento retornado por el motor es publicable.

## Contexto del LLM

El prompt se construye por capacidades mínimas:

- El hablante recibe sus objetivos, límites, datos públicos y su propio manifiesto de referencias privadas.
- La contraparte aporta únicamente perfil y hechos públicos.
- El transcript reciente se serializa con una lista explícita de campos seguros.
- Las referencias privadas de turnos anteriores no se serializan, incluso si el turno fue aprobado.

Las instrucciones del proveedor prohíben copiar o inventar referencias. Esta instrucción ayuda al modelo, pero no reemplaza la comprobación determinística de propiedad realizada por el guardrail.

Como `DataRequest.purpose` también forma parte del transcript, el guardrail aplica allí los mismos detectores de datos crudos y referencias propias usados para el mensaje público. El formato estructurado no convierte automáticamente un texto libre en seguro.

## Consecuencias

- Aprobar una divulgación ya no transmite automáticamente la referencia al otro agente.
- La categoría aprobada sigue disponible para explicar el turno y continuar el diálogo.
- La solicitud de aprobación interna conserva la referencia para auditoría y para una futura capa segura de resolución.
- El transporte y la persistencia deben respetar la audiencia; registrar o publicar todos los eventos sin filtrarlos violaría la frontera.
- La resolución del valor real y su entrega por un canal autorizado siguen fuera del alcance del AI Brain actual.
