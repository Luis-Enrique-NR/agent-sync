# Seam de administración Portal
- **Estado:** Completada
- **Fecha:** 2026-08-08
- **Rama:** `fix/portal-access-administration`

## Contexto
Backend debe ejecutar comandos autorizados sin convertir el transporte en una fuente de decisiones de negocio.

## Decisión
`PortalAdmin` expone solo `execute(AuthorizedPortalCommand)`. La unión cerrada incluye publicación y operaciones de acceso documentadas; no acepta método, path o cuerpo arbitrarios. `HttpPortalClient` vive durante el lifespan, usa `https://api.useportal.co` y `Authorization: Bearer` únicamente del lado servidor. `RecordingPortalAdmin` devuelve los mismos resultados tipados sin red.

| Comando tipado | Operación Portal | Resultado |
|---|---|---|
| `AddChannelMembers` | `POST /v1/channels/{channelId}/members` | `CommandApplied(added=int)` |
| `RemoveChannelMember` | `DELETE /v1/channels/{channelId}/members/{userId}` | `CommandApplied` |
| `BanChannelUser` | `POST /v1/channels/{channelId}/bans` | `CommandApplied` |
| `UnbanChannelUser` | `DELETE /v1/channels/{channelId}/bans/{userId}` | `CommandApplied` |

Los identificadores de canal y usuario se codifican para path. Un miembro se envía como cuerpo único y varios como `members` (máximo 100). El ban admite solo `userId` y `expiresAt`; no incorpora un campo `reason` no documentado. Quitar o levantar un ban conserva la semántica idempotente de Portal.

## Consecuencias, riesgos y pendiente
Un timeout de cualquier mutación devuelve resultado incierto y nunca se reintenta automáticamente. `429` y `5xx` devuelven `PortalRetryable(rate_limited|transient)` para que el llamador decida; el adaptador no reintenta. Los demás errores Portal se preservan como `PortalRejected(code, reason)`. Un `200` de agregar miembros requiere `added` como `int` real: ausencia, booleano u otro tipo devuelven `PortalRejected(invalid_response)`. El adaptador ejecuta comandos que ya fueron autorizados; no decide membresía, bans, ciclo de vida de canales ni políticas.
